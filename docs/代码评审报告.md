## 详细发现

### CR-001: SpEL表达式RCE风险 [高]

| 项 | 详情 |
| :--- | :--- |
| **严重级别** | 高 |
| **影响文件** | `backend/src/main/java/com/maike/mdm/service/impl/ConstraintServiceImpl.java`、`backend/src/main/java/com/maike/mdm/service/impl/WorkflowServiceImpl.java` |
| **问题描述** | 约束规则引擎和工作流引擎使用不受限SpEL表达式评估，可通过`T(..)`调用导致潜在远程代码执行（RCE） |
| **影响范围** | 约束规则条件表达式、工作流网关条件表达式、自动审核条件 |
| **修复建议** | 使用受限的SpEL配置（禁用T()等类型访问）或改用白名单表达式引擎，对约束/工作流配置做服务端校验，拒绝危险模式 |
| **当前状态** | 修复中 — 已派发至Robin，加入SafeSpelEvaluator安全评估器 |

### CR-002: SQL注入风险 [高]

| 项 | 详情 |
| :--- | :--- |
| **严重级别** | 高 |
| **影响文件** | `backend/src/main/java/com/maike/mdm/service/impl/CodeRuleServiceImpl.java` |
| **问题描述** | 编码规则SQL_EXPR段直接拼接SQL并执行，变量值未参数化，存在SQL注入风险 |
| **影响范围** | 编码规则SQL表达式段、审核人策略SQL表达式 |
| **修复建议** | 使用预编译参数绑定重写SQL表达式段，或对占位符值做严格类型和字符白名单校验 |
| **当前状态** | 修复中 — 已派发至Robin，改为NamedParameterJdbcTemplate参数化查询 |

### CR-003: 敏感信息硬编码 [中]

| 项 | 详情 |
| :--- | :--- |
| **严重级别** | 中 |
| **影响文件** | `backend/src/main/resources/application.yml` |
| **问题描述** | JWT签名密钥和数据库连接密码以明文硬编码在配置文件中 |
| **修复建议** | 迁移到环境变量或配置中心，使用Jasypt加密敏感属性 |
| **当前状态** | 建议生产部署前完成 |

## 架构评价

### 后端架构

- **RBAC权限体系**：PermissionService + DataScope注解 + DataScopeAspect，实现基于用户组和组织的行级数据权限控制，设计与现有RBAC体系一致，扩展性强
- **工作流引擎**：网关逻辑清晰，排他/并行/包容三种网关策略模式设计优雅，会签百分比阈值和自动审核表达式触发机制完整
- **约束规则引擎**：支持9种约束类型，采用ValidatorChain责任链模式，SpEL表达式配置灵活，易于扩展新约束类型
- **编码规则引擎**：8种段类型实现统一SegmentGenerator接口，流水号管理支持段间关联重置，层级码独立规则设计合理
- **数据导入导出**：EasyExcel轻量高效，普通导入/初始化导入/批量编辑三种模式覆盖完整业务场景
- **ESB重试机制**：组件级+接口级双层重试，指数退避策略设计健壮，异常通知支持多渠道

### 前端架构

- **权限控制**：auth store统一管理token、角色、权限和菜单树，路由层基于菜单动态注入业务路由，整体分层清晰
- **v-auth指令**：自定义Vue指令实现按钮级权限控制，权限标识格式统一（`类型:模块:操作`），使用便捷
- **路由守卫**：未登录时统一跳转登录页，首个请求时加载菜单和权限，兼顾权限控制与向后兼容
- **页面重设计**：Dashboard数据驾驶舱、MainData高级查询、DataReview批量审核，三个核心页面功能与体验均有显著提升

### 代码规范

- 后端统一使用Lombok简化实体类，命名规范一致
- 前端采用Composition API + `<script setup>`模式，代码组织清晰
- API接口统一返回`ApiResponse<T>`包装结构，HTTP状态码与业务状态码分离
- 数据库字段命名采用下划线风格，@TableField注解与数据库列名严格匹配

---

## 安全审查

- 后端认证与授权基于JWT + Spring Security，除登录和文档外接口均需认证，未发现明显未保护的管理接口
- JWT中roles和permissions从Claims注入SecurityContext，权限粒度能支持基于角色和功能点的控制
- 编码规则引擎新增SQL_EXPR段和层级码查询，存在基于配置的SQL注入风险，需通过参数绑定或白名单约束降低风险
- 约束规则引擎和工作流引擎广泛使用SpEL表达式，当前未限制类型访问，理论上可被利用执行任意Java代码，应视为高风险配置能力
- 上述两个安全问题已派发修复任务，修复后风险可控

---

## 结论

代码质量整体良好，架构清晰，命名规范统一。RBAC权限体系前后端双层控制设计合理，工作流引擎网关逻辑和会签机制完整，约束规则引擎和编码规则引擎扩展性强。两个高风险安全问题（SpEL RCE和SQL注入）已安排修复，修复方案明确，修复后可视为通过评审。

**综合评定: PASS** — 高风险问题修复完成后即可合并发布。
