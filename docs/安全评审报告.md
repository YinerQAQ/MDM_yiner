## 详细发现

### 高风险（已修复/修复中）

#### SEC-001: SpEL表达式远程代码执行（RCE）

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 高 |
| **影响文件** | `ConstraintServiceImpl.java`、`WorkflowServiceImpl.java` |
| **问题描述** | 约束规则引擎和工作流引擎使用不受限SpEL表达式评估，攻击者可通过`T(java.lang.Runtime).getRuntime().exec(...)`调用导致远程代码执行 |
| **攻击向量** | 构造恶意SpEL表达式注入到约束规则配置或工作流网关条件中 |
| **影响范围** | 服务器完全接管，数据泄露/篡改/删除 |
| **修复方案** | 已加入SafeSpelEvaluator安全评估器，禁止T()类型访问、反射调用和危险类加载 |
| **当前状态** | 修复中（Robin执行） |

#### SEC-002: SQL注入漏洞

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 高 |
| **影响文件** | `CodeRuleServiceImpl.java` |
| **问题描述** | 编码规则SQL_EXPR段使用字符串拼接构造SQL，变量值直接嵌入SQL语句，存在SQL注入风险 |
| **攻击向量** | 通过编码规则配置注入恶意SQL片段，读取/修改/删除数据库数据 |
| **影响范围** | 数据库数据泄露、篡改，可能获取数据库管理员权限 |
| **修复方案** | 已改为NamedParameterJdbcTemplate参数化查询，变量值通过绑定参数传入 |
| **当前状态** | 修复中（Robin执行） |

### 中风险（建议后续处理）

#### SEC-003: JWT Secret硬编码

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 中 |
| **影响文件** | `application.yml` |
| **问题描述** | JWT签名密钥和数据库连接密码以明文形式硬编码在配置文件中，源码泄露将导致认证绕过 |
| **修复建议** | 迁移到环境变量或配置中心（如Spring Cloud Config/Vault），使用Jasypt加密敏感属性 |
| **当前状态** | 建议生产部署前完成 |

#### SEC-004: 数据库root账户使用

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 中 |
| **影响文件** | `application.yml` |
| **问题描述** | 数据库连接使用root账户，拥有全部权限，违反最小权限原则 |
| **修复建议** | 创建专用数据库账户，仅授予MDM所需的最小权限集（SELECT/INSERT/UPDATE/DELETE） |
| **当前状态** | 建议生产部署前完成 |

### 低风险（可接受）

#### SEC-005: 前端降级模式显示所有菜单

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 低 |
| **影响文件** | `router/index.ts` |
| **问题描述** | 菜单数据为空时前端降级显示所有路由，可能导致未授权功能入口可见 |
| **缓解因素** | 后端@PreAuthorize注解已提供接口级权限校验兜底，即使前端可见也无法调用 |
| **当前状态** | 可接受，建议后续增加前端权限加载失败提示 |

#### SEC-006: Token 24小时有效期

| 项 | 详情 |
| :--- | :--- |
| **风险等级** | 低 |
| **影响文件** | `application.yml` |
| **问题描述** | JWT Token有效期设置为24小时，Token泄露窗口较大 |
| **缓解因素** | 支持Token刷新机制，可按业务需求调整有效期 |
| **当前状态** | 可接受，可根据业务安全要求缩短至2-8小时 |

## 安全架构评价

### 认证与授权

- JWT无状态认证设计合理，适合前后端分离架构
- Spring Security过滤链配置完整，登录/文档接口放行，其余接口均需认证
- @PreAuthorize方法级权限 + v-auth指令前端控制，形成双重授权校验
- 用户角色和权限从JWT Claims注入SecurityContext，避免频繁查询数据库

### 数据安全

- BCrypt密码加密，盐值随机生成，抗彩虹表攻击
- DataScope AOP切面自动注入数据范围条件，ID来源于系统内部上下文，无用户可控注入点
- 审计日志切面记录关键操作，支持事后追溯

### 防护机制

- Vue框架默认HTML转义，有效防止反射型XSS
- 无Cookie认证机制，天然免疫CSRF攻击
- 全局异常处理器统一错误响应，避免堆栈信息泄露

### 传输安全

- 建议生产环境强制HTTPS，当前开发环境未配置
- API通信使用Bearer Token认证，Token通过Authorization头传输

## 结论

系统整体安全架构设计合理，JWT + Spring Security + RBAC权限体系形成了完整的认证授权闭环。两个高风险安全问题（SpEL RCE和SQL注入）已识别并安排修复，修复方案明确（SafeSpelEvaluator + 参数化查询），修复后风险可降至低等级。中风险项（敏感信息硬编码）建议在生产部署前完成外部化配置迁移。
