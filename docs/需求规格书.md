## 2. 项目概述

### 2.1 系统定位

MDM（Master Data Management）主数据管理系统是面向企业的核心主数据全生命周期管理平台。系统聚焦数据标准制定、主数据业务处理、数据交换分发与数据安全管控四大核心领域，从源头确保主数据的规范性、准确性、完整性与一致性，并通过可配置、可监控、高可靠的方式将高质量主数据分发给下游各业务系统。

### 2.2 目标用户

| 角色 | 职责描述 |
| :--- | :--- |
| 申请人（数据提报人） | 提交主数据新增/变更/归档申请、查看本人相关数据与审批进展、撤销未审核数据 |
| 审核人 | 在审批节点审核/拒绝数据申请、转办、认领数据、提供审核意见 |
| 数据管理员 | 配置数据模型、绑定工作流、维护编码规则与约束规则、配置数据交换接口、管理数据归档 |
| 运维管理员（系统管理员） | 负责系统运维、创建/删除用户和单位、维护基础配置、菜单配置、系统设置 |
| 安全保密管理员（safeadmin） | 三员模式下负责用户启停、密码重置、密级配置、角色与用户组的权限分配 |
| 安全审计员（safeaudit） | 三员模式下负责对系统管理员与安全保密管理员操作的独立审计监督 |

### 2.3 业务范围

本期实施范围涵盖以下五大模块：

- **数据标准模块**：数据模型全生命周期管理、编码规则管理、约束规则管理、安全配置、页面配置、扩展配置、流程绑定、分类配置维护、同名库、主题域
- **数据业务模块**：数据查询、数据新增申请（手工填写/在线新增/普通导入/初始化导入/批量编辑/复制添加）、数据变更申请、数据审核、数据归档、历史版本管理
- **数据交换模块**：数据分发（同步/异步、即时/定时/手动）、ESB流程编排、服务监控、异常告警
- **数据安全模块**：权限管理（用户/角色/用户组/单位权限/分类权限/属性权限/数据记录控制）、属性脱敏、属性加密、密级管理、三员管理
- **管理中心模块**：流程管理、组织及权限管理、基础配置、监控中心

### 2.4 当前实现度说明

截至v2.0需求基准，系统已实现约37%的基础能力：

- **已实现**：基础登录认证、用户/角色/组织/菜单/字典管理、数据模型基础CRUD、编码规则基础管理、约束规则基础配置、主数据基础CRUD与状态流转、工作流基础定义与任务审批（通过/拒绝/转办/认领/取消认领）、数据分发与监控基础页面、ESB基础接口、Dashboard基础面板、审计日志

### 3.1 RBAC权限体系（P0）

#### FR-RBAC-001: 菜单权限控制

- **需求ID**：FR-RBAC-001
- **需求描述**：系统支持基于角色的菜单级权限控制。角色可配置可见的功能菜单范围，未授权菜单对用户不可见且不可访问。内置四个角色（申请人、审核人、数据管理员、运维管理员），支持自定义角色并按需分配菜单权限。
- **优先级**：P0
- **验收标准**：
  1. 角色管理界面支持勾选该角色可见的菜单节点
  2. 用户登录后，前端侧边栏仅渲染该用户所有角色并集范围内的菜单
  3. 直接访问未授权菜单路由时，系统拦截并提示无权限
  4. 菜单权限变更后，用户重新登录生效

#### FR-RBAC-002: 按钮级操作权限

- **需求ID**：FR-RBAC-002
- **需求描述**：在菜单权限基础上，系统需支持页面内按钮/操作级权限控制。同一页面内不同角色的用户可见的操作按钮不同（如申请人不可见"审核通过"按钮，审核人不可见"提交审核"按钮）。
- **优先级**：P0
- **验收标准**：
  1. 按钮权限与菜单权限在同一配置界面维护
  2. 前端按钮根据用户权限动态显隐，无权限按钮不渲染
  3. 后端对应接口同步校验权限，防止越权调用
  4. 覆盖主数据查询页、数据申请页、数据审核页、模型管理页等核心页面的操作按钮

#### FR-RBAC-003: 数据范围控制

- **需求ID**：FR-RBAC-003
- **需求描述**：系统支持四种数据范围控制策略，按用户组配置：全部（查看所有单位数据）、本部门（仅查看用户所属单位数据）、本部门及下级（查看用户所属单位及其所有下级单位数据）、仅本人（仅查看本人创建的数据）。单位权限控制方式支持"级联"（含下级）和"精确"（仅自身单位）两种。
- **优先级**：P0
- **验收标准**：
  1. 用户组管理界面支持为每个用户组配置数据范围策略
  2. 主数据查询、数据申请、数据审核等列表页按数据范围过滤结果
  3. 用户属于多个用户组时，数据范围取并集
  4. 单位权限支持级联与精确两种模式，在系统设置中可全局配置

#### FR-RBAC-004: 动态菜单渲染

- **需求ID**：FR-RBAC-004
- **需求描述**：前端菜单根据当前登录用户的角色权限动态生成，支持多级嵌套菜单。菜单数据来源于后端配置的菜单树，前端在登录时获取并缓存，结合路由守卫实现权限控制。
- **优先级**：P0
- **验收标准**：
  1. 后端提供 `/api/v1/menus/tree` 接口返回当前用户可见的菜单树
  2. 前端 Layout.vue 的侧边栏根据菜单树动态渲染
  3. 支持菜单图标、排序、层级关系的动态配置
  4. 菜单数据变更后，用户重新登录自动更新

#### FR-RBAC-005: 权限指令（v-auth）

- **需求ID**：FR-RBAC-005
- **需求描述**：前端提供自定义 Vue 指令 `v-auth`，用于在模板层面快速控制元素显隐。指令值为权限标识字符串，当当前用户不具备该权限时，元素自动隐藏。
- **优先级**：P1
- **验收标准**：
  1. 注册全局指令 `v-auth="'btn:mainData:approve'"`
  2. 指令内部调用权限校验逻辑，无权限时移除元素或设置 `display: none`
  3. 权限标识格式统一为 `类型:模块:操作`，如 `btn:dataReview:approve`
  4. 在 DataReview、MainData、DataApply 等核心页面应用该指令

### 3.2 工作流引擎（P0）

#### FR-WF-001: 排他网关（条件分支）

- **需求ID**：FR-WF-001
- **需求描述**：流程设计器支持排他网关（Exclusive Gateway，X），用于实现条件互斥的分支选择。到达排他网关时，系统按连线配置的优先级依次评估条件表达式，仅选择第一条满足条件的分支执行；若无条件满足，则走默认流。一个排他网关只能有一条连线设为默认流。
- **优先级**：P0
- **验收标准**：
  1. 流程设计器左侧组件区提供"排他网关"节点
  2. 支持拖拽排他网关到画布，并配置多条出连线
  3. 每条连线可配置条件表达式（支持 BeanShell / 简单字段判断）
  4. 流程实例运行时，排他网关正确选择唯一分支

#### FR-WF-002: 并行网关（同时激活）

- **需求ID**：FR-WF-002
- **需求描述**：流程设计器支持并行网关（Parallel Gateway，+），用于实现多分支并发执行。进入并行网关后，所有出连线分支同时激活；所有分支均完成后，在汇聚并行网关处等待汇总，全部完成才继续向下流转。
- **优先级**：P0
- **验收标准**：
  1. 流程设计器支持"并行网关"节点的拖拽与连线
  2. 并行分支中的任务节点可同时生成多个待办任务
  3. 并行汇聚网关等待所有分支完成后才触发后续节点
  4. 并行网关支持分支嵌套

#### FR-WF-003: 包容网关（条件激活）

- **需求ID**：FR-WF-003
- **需求描述**：流程设计器支持包容网关（Inclusive Gateway），用于实现条件激活的部分分支并行。到达包容网关时，评估所有出连线条件，满足条件的分支全部激活并并行执行；在汇聚处等待所有被激活的分支完成后继续流转。
- **优先级**：P0
- **验收标准**：
  1. 流程设计器支持"包容网关"节点
  2. 流程运行时，同时满足条件的多个分支并发激活
  3. 汇聚网关正确识别哪些分支被激活并等待它们全部完成
  4. 支持默认流机制，当无分支条件满足时走默认分支

#### FR-WF-004: 会签（百分比阈值）

- **需求ID**：FR-WF-004
- **需求描述**：审核节点支持会签模式。会签以已审用户百分比阈值作为通过条件：阈值为0或空时，任何一人审核通过即通过；阈值大于0时，需达到该比例的用户数审核通过后节点才通过。会签节点分配给多人时，所有被分配人同时收到待办。
- **优先级**：P0
- **验收标准**：
  1. 审核节点配置面板支持开启"会签"开关
  2. 支持配置百分比阈值（0~100）
  3. 阈值为0时，1人通过即节点通过，其他待办自动取消
  4. 阈值大于0时，按实际分配人数计算需通过人数（向上取整），达到后节点通过

#### FR-WF-005: 自动审核（表达式触发）

- **需求ID**：FR-WF-005
- **需求描述**：审核节点支持自动审核功能。系统可配置自动审核条件表达式或SQL条件，当流程到达该节点时自动评估：条件满足则自动通过，无需人工干预。自动审核支持3个内置变量：`flow.initiator`（发起人）、`flow.assignee`（前一审核人）、`flow.candidators`（待审人集合）。
- **优先级**：P0
- **验收标准**：
  1. 审核节点配置面板支持"自动审核"开关
  2. 支持配置 BeanShell 表达式或 SQL 条件作为自动审核规则
  3. 流程到达节点时自动执行评估，满足条件则自动流转
  4. 自动审核记录留痕，在流程实例日志中标记为"系统自动通过"

#### FR-WF-006: 超期自动处理

- **需求ID**：FR-WF-006
- **需求描述**：审核节点支持超期自动处理。可配置超期时长（N小时，仅工作日计算），到达节点后开始计时；超时未审核则系统自动处理。超期动作支持：审核通过、审核拒绝到前一节点、审核拒绝到开始节点。系统需维护节假日日历，超时计算剔除节假日。
- **优先级**：P0
- **验收标准**：
  1. 审核节点配置面板支持"超期自动处理"开关
  2. 支持配置超期时长（小时数）和超期动作类型
  3. 超时计算仅统计工作日，需支持节假日维护
  4. 超期后系统自动执行配置动作并留痕

#### FR-WF-007: 审核人策略（7种）

- **需求ID**：FR-WF-007
- **需求描述**：审核节点支持7种指定审核人策略，用于动态确定实际审核人：
  1. 指定用户：直接选择固定用户
  2. 指定用户组：选择用户组，组内成员均为审核候选人
  3. 发起人上级：根据发起人所在组织自动查找其上级
  4. 前一审核人上级：根据前一节点审核人查找其上级
  5. SQL表达式：通过SQL查询动态返回用户列表
  6. 部门主管：根据指定部门自动查找主管
  7. 角色：选择角色，拥有该角色的用户均为候选人
  支持单选/多选配置，以及审核人过滤SQL（基于 `#{users}` 和主表字段参数过滤）。
- **优先级**：P0
- **验收标准**：
  1. 审核节点配置面板支持7种策略的选择与配置
  2. 每种策略配置后能正确解析出审核候选人列表
  3. 审核人过滤SQL在候选人基础上二次过滤
  4. 流程运行时根据策略动态生成待办任务

### 3.3 约束规则引擎（P0）

#### FR-CST-001: 属性上下限校验

- **需求ID**：FR-CST-001
- **需求描述**：约束规则引擎支持属性上下限校验。针对数值型、日期型属性，可配置最小值和最大值范围；数据保存或提交时，校验属性值是否在设定范围内。校验失败时根据规则类型（错误型/警告型）决定阻止保存或仅提示。
- **优先级**：P0
- **验收标准**：
  1. 约束规则配置界面支持选择属性并设置上下限
  2. 支持数值、日期两种数据类型的范围校验
  3. 错误型校验失败阻止保存，警告型校验失败允许保存但返回警告信息
  4. 配置条件表达式，仅在满足前置条件时才执行该校验

#### FR-CST-002: 属性组必填校验

- **需求ID**：FR-CST-002
- **需求描述**：约束规则引擎支持属性组必填校验。同一组内的多个属性可配置为"全部必填"、"全部不填"或"至少填一个"三种模式。数据保存时按配置校验属性组内各属性的填写情况。
- **优先级**：P0
- **验收标准**：
  1. 支持将多个属性归入一个属性组并配置校验模式
  2. "全部必填"模式下，组内任一属性为空则校验失败
  3. "全部不填"模式下，组内任一属性有值则校验失败
  4. "至少填一个"模式下，组内全部为空则校验失败

#### FR-CST-003: 属性组主从必填校验

- **需求ID**：FR-CST-003
- **需求描述**：约束规则引擎支持属性组主从必填校验。配置主属性和从属性集合，当主属性填写（非空）时，从属性集合中指定字段必须填写；主属性为空时，从属性无强制要求。
- **优先级**：P0
- **验收标准**：
  1. 支持选择一个主属性和一个或多个从属性
  2. 主属性有值时，从属性必填校验生效
  3. 主属性为空时，从属性必填校验不生效
  4. 支持配置条件表达式控制该校验的生效范围

#### FR-CST-004: 属性关联校验（跨模型）

- **需求ID**：FR-CST-004
- **需求描述**：约束规则引擎支持跨模型属性关联校验。可配置规则：X模型的A字段值必须在（或不存在于）Y模型的B字段范围内。系统在校验时查询目标模型数据，验证关联关系是否成立。支持配置条件表达式和校验范围SQL进一步限定。
- **优先级**：P0
- **验收标准**：
  1. 支持选择源模型属性、目标模型、目标属性
  2. 支持"必须存在"和"必须不存在"两种关联模式
  3. 支持配置校验范围SQL进一步缩小目标数据范围
  4. 支持条件表达式，仅在满足前置条件时执行

#### FR-CST-005: 自定义校验表达式

- **需求ID**：FR-CST-005
- **需求描述**：约束规则引擎支持自定义校验表达式。可配置 BeanShell 表达式或 SQL 表达式来自定义校验逻辑，满足复杂业务规则场景。表达式中可引用当前数据对象的字段值。
- **优先级**：P0
- **验收标准**：
  1. 约束规则配置界面支持输入 BeanShell 或 SQL 表达式
  2. 表达式可引用当前主数据实体的字段（字段名小写）
  3. 表达式返回布尔值，true表示校验通过，false表示失败
  4. 校验失败时返回配置的提示信息

#### FR-CST-006: 变更校验控制

- **需求ID**：FR-CST-006
- **需求描述**：约束规则引擎支持变更阶段的字段控制校验。根据某个下拉字段的值，确定其他字段在变更流程中的校验规则：不可变更、必须变更、变更后值大于/小于原值等。仅在数据变更流程中生效。
- **优先级**：P0
- **验收标准**：
  1. 支持配置"控制字段"（通常为下拉选择）和"受控字段"
  2. 支持配置控制字段各选项对应的受控规则（不可变更/必须变更/大于/小于）
  3. 仅在变更流程中校验，新增流程不生效
  4. 校验失败时给出明确字段级提示

#### FR-CST-007: 模型主从控制

- **需求ID**：FR-CST-007
- **需求描述**：约束规则引擎支持主从模型提交校验。针对主从结构的数据模型，在提交时校验从模型数据是否满足要求：全部必填（所有从表记录必须完整）、指定必填（指定从表记录必须完整）、至少N条（从表记录数不少于N）。此为提交型校验，保存时跳过。
- **优先级**：P0
- **验收标准**：
  1. 支持配置"全部必填"、"指定必填"、"至少N条"三种模式
  2. "指定必填"模式下可选择具体从表字段要求非空
  3. 仅在数据提交审核时触发，暂存保存不校验
  4. 校验失败阻止提交并提示具体缺失内容

#### FR-CST-008: 附件必填校验

- **需求ID**：FR-CST-008
- **需求描述**：约束规则引擎支持附件必填校验。在数据提交时校验是否已上传附件，支持配置条件表达式：仅在满足条件时才要求附件必填。此校验为提交型校验。
- **优先级**：P0
- **验收标准**：
  1. 支持配置附件必填规则及条件表达式
  2. 条件满足时，提交审核校验附件是否已上传
  3. 暂存保存时不触发附件必填校验
  4. 支持按模型和属性粒度配置

#### FR-CST-009: 一对多实体变更校验控制

- **需求ID**：FR-CST-009
- **需求描述**：约束规则引擎支持一对多实体在变更阶段的删除控制。可配置规则禁止在变更流程中删除原有的一对多从表数据记录，仅允许新增或修改已有记录。
- **优先级**：P0
- **验收标准**：
  1. 支持配置"变更时禁止删除原有数据"开关
  2. 仅在数据变更流程中生效
  3. 用户尝试删除原有从表记录时系统拦截并提示
  4. 支持配置例外条件表达式

### 3.4 编码规则引擎（P1）

#### FR-CODE-001: 数字流水段

- **需求ID**：FR-CODE-001
- **需求描述**：编码规则支持数字流水段类型。按配置的起始值、步长、位数生成数字流水码。支持段间关联：流水码可关联前段编码值，当前段值不变时流水继续递增，前段值变化时流水重新开始。
- **优先级**：P1
- **验收标准**：
  1. 支持配置起始值、步长、位数（如0001~9999）
  2. 支持配置关联前段，前段值变化时流水号重置
  3. 支持补零填充到指定位数
  4. 并发场景下流水号不重复

#### FR-CODE-002: 字母流水段

- **需求ID**：FR-CODE-002
- **需求描述**：编码规则支持字母流水段类型。按配置的起始字母、步长生成字母流水码（如A~Z、AA~ZZ）。支持与数字流水类似的段间关联逻辑。
- **优先级**：P1
- **验收标准**：
  1. 支持配置起始字母和步长
  2. 字母耗尽后支持进位（Z→AA）
  3. 支持关联前段重置逻辑
  4. 并发场景下流水号不重复

#### FR-CODE-003: 首字母流水段

- **需求ID**：FR-CODE-003
- **需求描述**：编码规则支持首字母流水段类型。根据关联属性的中文/英文值自动提取首字母并追加流水号（如"北京"→BJ001）。适用于按名称拼音首字母编码的场景。
- **优先级**：P1
- **验收标准**：
  1. 支持选择关联属性（名称类属性）
  2. 自动提取属性值的首字母（支持中英文）
  3. 首字母部分后追加数字流水
  4. 属性值变化时首字母部分重新提取

#### FR-CODE-004: 时间戳段

- **需求ID**：FR-CODE-004
- **需求描述**：编码规则支持时间戳段类型。根据当前日期时间生成格式化时间字符串，支持多种格式：yyyyMMdd、yyyyMM、yyyy、yyyyMMddHHmmss等。编码生成时取系统当前时间。
- **优先级**：P1
- **验收标准**：
  1. 支持选择日期时间格式模板
  2. 编码生成时取服务器当前时间
  3. 支持纯日期、日期+时间等多种粒度
  4. 时区与系统设置一致

#### FR-CODE-005: 随机码段（UUID / 时间戳+随机数）

- **需求ID**：FR-CODE-005
- **需求描述**：编码规则支持随机码段类型，包括UUID（标准32位UUID字符串）和时间戳+随机数（高唯一性短码）两种子类型。适用于不需要可读性但要求全局唯一的编码场景。
- **优先级**：P1
- **验收标准**：
  1. UUID类型生成标准32位UUID字符串（去掉横线）
  2. 时间戳+随机数类型生成含时间戳和随机数的组合码
  3. 随机码段不支持段间关联
  4. 全局唯一性概率接近100%

#### FR-CODE-006: BeanShell / SQL 表达式段

- **需求ID**：FR-CODE-006
- **需求描述**：编码规则支持表达式段类型。可编写 BeanShell 表达式或 SQL 查询来动态生成编码片段。表达式中可引用数据对象字段值和系统变量，实现高度灵活的编码逻辑。
- **优先级**：P1
- **验收标准**：
  1. 支持 BeanShell 表达式和 SQL 查询两种模式
  2. 表达式可引用当前数据字段和系统内置变量
  3. SQL 查询返回单行单列结果作为编码片段
  4. 表达式执行异常时给出明确错误提示

#### FR-CODE-007: 引用值段

- **需求ID**：FR-CODE-007
- **需求描述**：编码规则支持引用值段类型。选择当前数据模型中的某个属性，编码生成时取该属性的当前值作为编码片段。适用于编码中包含分类码、组织码等已有属性值的场景。
- **优先级**：P1
- **验收标准**：
  1. 支持选择当前模型下的任意属性作为引用源
  2. 编码生成时动态取属性当前值
  3. 引用属性为空时按配置处理（跳过/报错/默认值）
  4. 支持关联前段重置逻辑

#### FR-CODE-008: 层级码段

- **需求ID**：FR-CODE-008
- **需求描述**：编码规则支持层级码段类型。按配置的层级长度和分隔符生成层级编码（如1.01.001）。层级码不允许与其他类型编码段同时生成编码。支持按父节点编码自动计算下一级编码。
- **优先级**：P1
- **验收标准**：
  1. 支持配置每层级长度和分隔符
  2. 层级码独立成规则，不与其他段类型混用
  3. 支持按父编码自动推断子编码
  4. 层级结构变化时编码重新计算

### 3.5 数据业务增强（P1）

#### FR-DATA-001: Excel导入（普通/初始化）

- **需求ID**：FR-DATA-001
- **需求描述**：系统支持通过Excel导入主数据，提供两种模式：
  - **普通导入**：下载模板→填写数据→上传导入→数据进入暂存状态→提交审核→审核通过后生效

  支持普通模板、自定义模板、多类别模板、主从模板。
- **优先级**：P1
- **验收标准**：
  1. 数据申请页面提供"下载模板"和"导入数据"按钮
  2. 模板根据模型属性动态生成，包含必填项标识
  3. 普通导入数据进入暂存状态，需提交审核
  4. 初始化导入数据直接生效，版本号为1
  5. 导入失败时返回详细错误行号和原因

#### FR-DATA-002: Excel/CSV导出

- **需求ID**：FR-DATA-002
- **需求描述**：系统支持主数据的Excel和CSV格式导出。数据查询界面支持导出当前查询结果（受查询条件过滤），导出内容需遵循属性权限控制（无查看权限的字段不导出）、属性脱敏规则（脱敏字段按脱敏格式导出）。
- **优先级**：P1
- **验收标准**：
  1. 数据查询页支持Excel(.xlsx)和CSV(.csv)两种导出格式
  2. 导出内容受当前查询条件和分页影响（可选导出全部或当前页）
  3. 导出字段遵循属性权限和脱敏规则
  4. 大数据量导出采用异步任务，完成后通知下载

#### FR-DATA-003: 批量编辑

- **需求ID**：FR-DATA-003
- **需求描述**：系统支持主数据的批量编辑。在数据查询界面勾选多条数据（相同模型），选择"批量编辑"，在批量编辑界面修改公共字段的值，保存后所有选中数据同步更新。批量编辑后的数据进入变更审核流程。
- **优先级**：P1
- **验收标准**：
  1. 数据查询页支持多选数据并点击"批量编辑"
  2. 批量编辑界面仅显示选中数据共有的可编辑字段
  3. 保存后每条数据生成独立的变更记录
  4. 批量编辑的数据进入审核流程，审核通过后生效
  5. 仅支持审核通过状态的数据发起批量编辑

### 3.6 ESB数据交换（P1）

#### FR-ESB-001: 失败重试机制

- **需求ID**：FR-ESB-001
- **需求描述**：数据分发接口支持失败重试机制，分为接口级和组件级两层。组件级重试优先执行（单个ESB组件调用失败后重试），接口级重试在组件级全部完成后执行（整个分发流程失败后重试）。支持配置重试次数和间隔时间。请求ESB超时时间支持10s~600s配置。
- **优先级**：P1
- **验收标准**：
  1. 分发接口配置界面支持配置重试次数（1~10次）和重试间隔（秒）
  2. 组件级重试在单个组件失败时触发，不影响其他组件
  3. 接口级重试在整个流程失败后触发，重新执行完整分发流程
  4. 重试记录在服务监控界面可查看

#### FR-ESB-002: 定时分发

- **需求ID**：FR-ESB-002
- **需求描述**：数据分发接口支持定时同步类型。通过配置 Cron 表达式实现周期性的数据分发任务。支持配置单次分发记录数上限，防止单次任务数据量过大。定时分发任务在后台调度执行，执行结果写入分发记录表。
- **优先级**：P1
- **验收标准**：
  1. 分发接口支持选择"定时同步"类型
  2. 支持配置标准 Cron 表达式
  3. 支持配置单次分发最大记录数
  4. 定时任务触发后，符合条件的数据自动加入待分发列表
  5. 定时分发执行记录可在监控中心查看

#### FR-ESB-003: 异常通知与监控

- **需求ID**：FR-ESB-003
- **需求描述**：数据分发接口支持异常通知配置。当分发失败时，系统可按配置的通知方式发送告警：系统消息提醒、邮件提醒、通知公告。通知接收人可配置为用户组。异常信息记录到 `MDM_ESB_EXCEPTION` 表，在服务监控界面可查看待同步/已同步/分发失败/分发日志。
- **优先级**：P1
- **验收标准**：
  1. 分发接口配置向导支持"异常处理"步骤
  2. 支持配置消息提醒、邮件提醒、通知公告三种方式（可多选）
  3. 支持选择接收通知的用户组
  4. 分发失败时自动触发通知
  5. 服务监控页面支持按状态筛选分发记录

### 4.2 安全需求

| 需求项 | 要求 |
| :--- | :--- |
| 身份认证 | 基于JWT Token的无状态认证，Token有效期可配置，支持刷新机制 |

| 传输安全 | 所有API通信使用HTTPS加密传输 |
| 密级控制 | 附件密级 ≤ 数据密级 ≤ 用户最高文件密级，适用于所有操作含暂存 |

| 数据记录控制 | 分"默认规则"（全体用户）和"非默认规则"（指定用户组），两者互斥；多用户组取条件交集 |
| IP黑名单 | 登录失败超过阈值次数自动锁定IP，锁定N天后自动解锁 |
| 三员管理 | 系统管理员新建单位/用户默认停用，安全保密管理员启用；审计员仅查看日志 |
| 操作审计 | 关键操作（登录、增删改、审核、权限变更）记录审计日志，支持追溯 |

## 5. 验收标准

| :--- | :--- |
| AC-01 | 数据管理员能够完成完整的建模流程（基本配置 → 表配置 → 约束 → 编码 → 安全 → 页面 → 扩展 → 流程绑定 → 提交 → 审核发布），发布后模型在数据业务菜单可见 |

| AC-04 | 唯一约束和9种关联约束在数据保存/提交时正确校验，错误型校验阻止保存，警告型允许保存但有提示 |

| AC-10 | 失败重试机制生效（接口级+组件级），异常通知（消息/邮件/通知公告）在失败时正确触发 |
