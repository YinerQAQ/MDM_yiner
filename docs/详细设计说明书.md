#### 3.1.1 BASE_DATA_SCOPE 表（新建）

用于存储用户组的数据范围配置，实现FR-RBAC-003需求。

```sql
-- 数据范围配置表
CREATE TABLE IF NOT EXISTS BASE_DATA_SCOPE (
    ID VARCHAR(64) NOT NULL PRIMARY KEY,
    GROUP_ID VARCHAR(64) NOT NULL COMMENT '用户组ID',
    SCOPE_TYPE VARCHAR(36) NOT NULL COMMENT '范围类型: ALL-全部/DEPT-本部门/DEPT_AND_SUB-本部门及下级/SELF-仅本人',
    ORG_CASCADE_FLAG VARCHAR(12) DEFAULT 'CASCADE' COMMENT '单位级联方式: CASCADE-级联(含下级)/EXACT-精确(仅自身)',
    CREATE_TIME DATETIME DEFAULT CURRENT_TIMESTAMP,
    UPDATE_TIME DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE INDEX UK_DATA_SCOPE_GROUP (GROUP_ID),
    FOREIGN KEY (GROUP_ID) REFERENCES BASE_GROUP(ID)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='数据范围配置表';
```

**字段说明**：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| ID | VARCHAR(64) | 主键 |
| GROUP_ID | VARCHAR(64) | 关联用户组，一个组一条配置 |
| SCOPE_TYPE | VARCHAR(36) | ALL=全部数据，DEPT=本部门，DEPT_AND_SUB=本部门及下级，SELF=仅本人 |
| ORG_CASCADE_FLAG | VARCHAR(12) | CASCADE=级联含下级单位，EXACT=仅自身单位 |

#### 3.1.3 MDM_WORKFLOW_NODE 添加字段

扩展工作流节点表以支持会签、自动审核、超期处理和审核人策略。

```sql
-- MDM_WORKFLOW_NODE 新增字段
ALTER TABLE MDM_WORKFLOW_NODE ADD COLUMN SIGN_PERCENT DECIMAL(5,2) DEFAULT NULL COMMENT '会签通过百分比阈值(0~100)，0表示任意一人通过即通过' AFTER SIGN_THRESHOLD;

ALTER TABLE MDM_WORKFLOW_NODE ADD COLUMN ASSIGNEE_STRATEGY VARCHAR(36) DEFAULT NULL COMMENT '审核人策略: FIXED_USER-指定用户/FIXED_GROUP-指定用户组/INITIATOR_SUPERIOR-发起人上级/PREV_ASSIGNEE_SUPERIOR-前一审核人上级/SQL_EXPR-SQL表达式/DEPT_MANAGER-部门主管/ROLE-角色' AFTER ASSIGNEE_VALUE;

ALTER TABLE MDM_WORKFLOW_NODE ADD COLUMN ASSIGNEE_STRATEGY_VALUE TEXT DEFAULT NULL COMMENT '审核人策略配置值(JSON格式)' AFTER ASSIGNEE_STRATEGY;

ALTER TABLE MDM_WORKFLOW_NODE ADD COLUMN ASSIGNEE_FILTER_SQL TEXT DEFAULT NULL COMMENT '审核人过滤SQL，可使用#{users}占位符' AFTER ASSIGNEE_STRATEGY_VALUE;
```

**ASSIGNEE_STRATEGY_VALUE JSON结构定义**（按策略类型不同）：

```json
// 1. FIXED_USER - 指定用户
{
  "userIds": ["user001", "user002"]
}

// 2. FIXED_GROUP - 指定用户组
{
  "groupIds": ["group001"]
}

// 3. INITIATOR_SUPERIOR - 发起人上级
{
  "level": 1  // 上级层级，1=直属上级
}

// 4. PREV_ASSIGNEE_SUPERIOR - 前一审核人上级
{
  "level": 1
}

// 5. SQL_EXPR - SQL表达式
{
  "sql": "SELECT ID FROM BASE_USER WHERE ORGID = '#{orgId}' AND STATUS = '启用'"
}

// 6. DEPT_MANAGER - 部门主管
{
  "orgId": "ORG001"  // 可为空，为空时取发起人所在部门
}

// 7. ROLE - 角色
{
  "roleIds": ["role003"]
}
```

#### 3.1.4 MDM_MODEL_CONSTRAINT 添加 CONSTRAINT_CONFIG 字段

现有 `CONFIG_JSON` 字段语义不够明确，新增 `CONSTRAINT_CONFIG` 字段以支持9种约束类型的标准化JSON配置。此字段与 `CONFIG_JSON` 并存，新逻辑优先读取 `CONSTRAINT_CONFIG`。

```sql
ALTER TABLE MDM_MODEL_CONSTRAINT ADD COLUMN CONSTRAINT_CONFIG JSON DEFAULT NULL COMMENT '约束详细配置(JSON格式)，按约束类型有不同的结构定义' AFTER CONFIG_JSON;
```

> **设计说明**：保留原 `CONFIG_JSON` 字段兼容存量数据。新增代码中优先读取 `CONSTRAINT_CONFIG`，为空时降级读取 `CONFIG_JSON`。

#### 3.1.7 MDM_IMPORT_TASK 表（新建）

数据导入任务表，支持普通导入和初始化导入（FR-DATA-001）。

```sql
CREATE TABLE IF NOT EXISTS MDM_IMPORT_TASK (
    ID VARCHAR(64) NOT NULL PRIMARY KEY,
    MODEL_ID VARCHAR(64) NOT NULL COMMENT '数据模型ID',
    IMPORT_TYPE VARCHAR(36) NOT NULL COMMENT '导入类型: NORMAL-普通导入/INIT-初始化导入',
    FILE_NAME VARCHAR(255) NOT NULL COMMENT '上传文件名',
    FILE_PATH VARCHAR(500) NOT NULL COMMENT '服务器文件路径',

    SUCCESS_COUNT INT DEFAULT 0 COMMENT '成功行数',
    FAIL_COUNT INT DEFAULT 0 COMMENT '失败行数',
    STATUS VARCHAR(36) DEFAULT 'UPLOADED' COMMENT '状态: UPLOADED-已上传/PARSING-解析中/PREVIEW-预览中/IMPORTING-导入中/COMPLETED-已完成/FAILED-失败',
```

## 4. RBAC权限设计

### 4.1 权限模型

**三级关联模型**：用户 → 角色 → 菜单(含PERMS)

```
┌────────┐    N:N    ┌────────┐    N:N    ┌────────────────┐
│BASE_USER│◄────────►│BASE_ROLE│◄────────►│   BASE_MENU    │
│        │           │        │           │(目录/菜单/按钮) │
└────┬───┘           └────┬───┘           │ + PERMS字段    │
     │                    │               └────────────────┘
     │ N:N               │ N:N
     ▼                    ▼
┌──────────┐        ┌──────────┐
│BASE_GROUP│◄──────►│BASE_ROLE │
│          │        │          │
└────┬─────┘        └──────────┘
     │ 1:1
     ▼
┌──────────────┐
│BASE_DATA_SCOPE│ ← 数据范围配置
└──────────────┘
```

**数据范围策略**（FR-RBAC-003）：

| SCOPE_TYPE | 含义 | SQL过滤逻辑 |
| :--- | :--- | :--- |
| ALL | 全部数据 | 无过滤 |
| DEPT | 本部门 | `WHERE CREATED_BY_ORGID = #{currentUserOrgId}` |
| DEPT_AND_SUB | 本部门及下级 | `WHERE CREATED_BY_ORGID IN (#{currentUserOrgId} + 所有下级ORGID)` |
| SELF | 仅本人 | `WHERE CREATED_BY_ID = #{currentUserId}` |

**多用户组取并集**：用户属于多个用户组时，各数据范围条件以OR连接。

```java
// 修改SecurityConfig.jwtAuthenticationFilter()中的Token解析逻辑
if (jwtUtil.validateToken(token)) {
    Claims claims = jwtUtil.extractAllClaims(token);
    String username = claims.getSubject();

    // 从Claims提取roles和permissions
    List<String> roles = claims.get("roles", List.class);
    List<String> permissions = claims.get("permissions", List.class);

    // 构建GrantedAuthority列表
    List<GrantedAuthority> authorities = new ArrayList<>();
    if (roles != null) {
        roles.forEach(r -> authorities.add(new SimpleGrantedAuthority("ROLE_" + r)));
    }
    if (permissions != null) {
        permissions.forEach(p -> authorities.add(new SimpleGrantedAuthority(p)));
    }

    UsernamePasswordAuthenticationToken auth =
        new UsernamePasswordAuthenticationToken(username, null, authorities);
    SecurityContextHolder.getContext().setAuthentication(auth);
}
```

```typescript
export function buildDynamicRoutes(menus: MenuItem[]): RouteRecordRaw[] {
  const routes: RouteRecordRaw[] = []

  function traverse(menuList: MenuItem[]) {
    for (const menu of menuList) {
      if (menu.menuType === '菜单' && menu.component && componentMap[menu.component]) {
        routes.push({
          path: menu.path || '/',
          name: menu.menuCode,
          component: componentMap[menu.component],
          meta: {
            title: menu.menuName,
            icon: menu.icon,
            perms: menu.perms
          }
        })
      }
      if (menu.children?.length) {
        traverse(menu.children)
      }
    }
  }

  traverse(menus)
  return routes
}
```

```typescript
// 修改 router/index.ts 的 beforeEach
router.beforeEach((to, _from, next) => {
  const authStore = useAuthStore()

  if (to.path === '/login') {
    next()
    return
  }

  if (!authStore.isLoggedIn()) {
    next('/login')
    return
  }

  // 首次加载或刷新后，重新注册动态路由
  if (!authStore.routesLoaded) {
    const dynamicRoutes = buildDynamicRoutes(authStore.menus)
    dynamicRoutes.forEach(route => {
      router.addRoute('Layout', route)

    authStore.routesLoaded = true
    next({ ...to, replace: true })  // 重新导航以匹配新路由
    return

  // 检查路由权限
  if (to.meta?.perms && !authStore.hasPermission(to.meta.perms as string)) {
    next('/403')  // 无权限页面
    return
  }

  next()
})
```

| INCLUSIVE_GW | 包容网关 | 条件激活部分分支并行（FR-WF-003） |

#### 5.1.1 排他网关执行算法

```
输入: 排他网关节点ID, 流程实例上下文(含主数据字段值)
输出: 下一节点ID

算法:
1. 查询该网关的所有出边, 按SORT_ORDER排序
2. 默认边标记为 IS_DEFAULT='1', 最多一条
3. 依次评估每条非默认边的 CONDITION_EXPR:
   a. 解析表达式中的变量引用: #{field_name}
   b. 从流程上下文(主数据JSON_DATA)中替换变量
   c. 使用BeanShell引擎求值, 返回boolean
4. 若某条边条件为true → 返回该边的目标节点
5. 所有非默认边条件均为false → 走默认边
6. 无默认边且无满足条件 → 抛出流程异常
```

**CONDITION_EXPR 示例**：

```bash
# 简单字段判断
#{amount} > 10000

# 字符串比较
#{urgency} == "紧急"

# 组合条件
#{amount} > 50000 && #{deptLevel} == "一级"
```

#### 5.1.2 并行网关执行算法

```
分支(并行网关进入):
1. 查询该网关的所有出边
2. 为每条出边的目标节点创建待办任务
3. 所有分支同时激活(并行执行)
4. 记录分支数到流程实例的并行分支计数器

汇聚(并行网关汇聚):
1. 当某个分支的最后一个任务完成时, 递减并行分支计数器
2. 计数器归零时, 所有分支均已完成 → 触发后续节点
3. 计数器未归零时, 等待其余分支完成

并行网关支持嵌套:
- 使用栈结构维护嵌套的分支计数器
- 每进入一个并行网关push计数器, 每汇聚完成pop计数器
```

**数据库支持**：在 `MDM_WORKFLOW_INSTANCE` 中新增字段：

```sql
ALTER TABLE MDM_WORKFLOW_INSTANCE ADD COLUMN PARALLEL_COUNTER TEXT DEFAULT NULL
    COMMENT '并行分支计数器(JSON栈)，格式: [{"gatewayNodeId":"gw1","remaining":3}]';
```

#### 5.1.3 包容网关执行算法

```
分支(包容网关进入):
1. 查询该网关的所有出边
2. 依次评估每条出边的 CONDITION_EXPR
3. 满足条件的分支全部激活(并行执行)
4. 无条件满足时走默认边(IS_DEFAULT='1')
5. 记录被激活的分支ID集合到流程实例

汇聚:
1. 仅等待被激活的分支完成
2. 所有已激活分支完成后 → 触发后续节点
3. 未被激活的分支跳过, 不参与汇聚等待
```

**数据库支持**：在 `MDM_WORKFLOW_INSTANCE` 中新增字段：

```java
/**
 * 会签处理逻辑
 * 对应需求: FR-WF-004
 */
public SignResult processSignApproval(String nodeId, String instanceId) {
    // 1. 获取节点会签配置
    MdmWorkflowNode node = getNode(nodeId);
    String signType = node.getSignType();        // SIGN-会签 / NULL-非会签
    BigDecimal signPercent = node.getSignPercent(); // 通过百分比阈值

    if (!"SIGN".equals(signType)) {
        return SignResult.NOT_SIGN_NODE; // 非会签节点，走普通审批
    }

    // 2. 查询该节点所有待办任务
    List<MdmWorkflowTask> allTasks = getTasksByNodeAndInstance(nodeId, instanceId);
    int totalAssignees = allTasks.size();

    // 3. 统计已审核情况
    long approvedCount = allTasks.stream()
        .filter(t -> "APPROVED".equals(t.getTaskStatus())).count();
    long rejectedCount = allTasks.stream()
        .filter(t -> "REJECTED".equals(t.getTaskStatus())).count();

    // 4. 判断会签结果
    if (signPercent == null || signPercent.compareTo(BigDecimal.ZERO) == 0) {
        // 阈值为0: 任意一人通过即通过
        if (approvedCount > 0) {
            cancelOtherPendingTasks(allTasks); // 取消其余待办
            return SignResult.PASSED;
        }
    } else {
        // 阈值>0: 需达到百分比
        int requiredCount = (int) Math.ceil(
            signPercent.doubleValue() / 100.0 * totalAssignees);
        if (approvedCount >= requiredCount) {
            cancelOtherPendingTasks(allTasks);
            return SignResult.PASSED;
        }
    }

    // 5. 所有人审核完但未达阈值 → 拒绝
    long completedCount = approvedCount + rejectedCount;
    if (completedCount >= totalAssignees) {
        return SignResult.REJECTED;
    }

    return SignResult.PENDING; // 仍在等待
}
```

```java
/**
 * 超期自动处理定时任务
 * 对应需求: FR-WF-006
 * Cron: 每30分钟执行一次
 */
@Component
@RequiredArgsConstructor
public class WorkflowTimeoutJob {

    private final MdmWorkflowTaskMapper taskMapper;
    private final MdmWorkflowNodeMapper nodeMapper;
    private final SysHolidayMapper holidayMapper;

    @Scheduled(cron = "0 */30 * * * ?")
    public void checkTimeoutTasks() {
        // 1. 查询所有待处理(pending)的任务
        List<MdmWorkflowTask> pendingTasks = taskMapper.selectPendingTasks();

        for (MdmWorkflowTask task : pendingTasks) {
            MdmWorkflowNode node = nodeMapper.selectById(task.getNodeId());
            if (node.getTimeoutHours() == null || node.getTimeoutHours() <= 0) {
                continue; // 未配置超期
            }

            // 2. 计算工作日耗时（剔除节假日和周末）
            long workedHours = calculateWorkingHours(
                task.getCreateTime(), LocalDateTime.now());

            // 3. 超期判断
            if (workedHours >= node.getTimeoutHours()) {
                // 4. 执行超期动作
                executeTimeoutAction(task, node);
            }
        }
    }

    /**
     * 计算工作日小时数（剔除周末和法定节假日，加入调休工作日）
     */
    private long calculateWorkingHours(LocalDateTime start, LocalDateTime end) {
        long hours = 0;
        LocalDateTime current = start;
        while (current.isBefore(end)) {
            LocalDate date = current.toLocalDate();
            if (isWorkingDay(date)) {
                // 简化: 每个工作日算8小时(9:00-18:00)
                hours += 8;
            }
            current = current.plusDays(1);
        }
        return hours;
    }

    private boolean isWorkingDay(LocalDate date) {
        DayOfWeek dow = date.getDayOfWeek();
        // 查询调休工作日
        if (holidayMapper.isWeekendWork(date)) return true;
        // 查询法定节假日
        if (holidayMapper.isHoliday(date)) return false;
        // 正常工作日(周一~周五)
        return dow != DayOfWeek.SATURDAY && dow != DayOfWeek.SUNDAY;
    }

    private void executeTimeoutAction(MdmWorkflowTask task, MdmWorkflowNode node) {
        String action = node.getTimeoutAction();
        switch (action) {
            case "APPROVE":           // 审核通过
                autoApproveTask(task, "系统自动通过(超期)");
                break;
            case "REJECT_TO_PREV":    // 拒绝到前一节点
                autoRejectTask(task, "系统自动拒绝(超期)", true);
                break;
            case "REJECT_TO_START":   // 拒绝到开始节点
                autoRejectTask(task, "系统自动拒绝(超期)", false);
                break;
        }
    }
}
```

```java
/**
 * 审核人策略解析器
 * 对应需求: FR-WF-007
 */
@Component
@RequiredArgsConstructor
public class AssigneeStrategyResolver {

    private final BaseUserMapper userMapper;
    private final BaseGroupMapper groupMapper;
    private final BaseOrgMapper orgMapper;
    private final BaseRoleMapper roleMapper;
    private final JdbcTemplate jdbcTemplate;

    /**
     * 根据策略解析审核候选人列表
     * @param strategy  策略类型
     * @param config    策略配置值(JSON)
     * @param context   流程上下文(initiatorId, prevAssigneeId等)
     * @return 候选人用户ID列表
     */
    public List<String> resolveCandidates(
            String strategy, String config, WorkflowContext context) {

        JSONObject cfg = JSON.parseObject(config);

        switch (strategy) {
            case "FIXED_USER":
                return cfg.getJSONArray("userIds").toJavaList(String.class);

            case "FIXED_GROUP":
                List<String> groupIds = cfg.getJSONArray("groupIds").toJavaList(String.class);
                return userMapper.selectUserIdsByGroupIds(groupIds);

            case "INITIATOR_SUPERIOR": {
                String orgId = context.getInitiatorOrgId();
                int level = cfg.getIntValue("level", 1);
                String superiorOrgId = findSuperiorOrg(orgId, level);
                return userMapper.selectManagerByOrgId(superiorOrgId);
            }

            case "PREV_ASSIGNEE_SUPERIOR": {
                String prevAssigneeId = context.getPrevAssigneeId();
                String prevOrgId = userMapper.selectOrgIdByUserId(prevAssigneeId);
                int level = cfg.getIntValue("level", 1);
                String superiorOrgId = findSuperiorOrg(prevOrgId, level);
                return userMapper.selectManagerByOrgId(superiorOrgId);
            }

            case "SQL_EXPR": {
                String sql = cfg.getString("sql");
                // 替换变量
                sql = sql.replace("#{orgId}", context.getInitiatorOrgId());
                sql = sql.replace("#{initiatorId}", context.getInitiatorId());
                // 执行SQL查询
                return jdbcTemplate.queryForList(sql, String.class);
            }

            case "DEPT_MANAGER": {
                String orgId = cfg.getString("orgId");
                if (orgId == null || orgId.isEmpty()) {
                    orgId = context.getInitiatorOrgId();
                }
                return userMapper.selectManagerByOrgId(orgId);
            }

            case "ROLE": {
                List<String> roleIds = cfg.getJSONArray("roleIds").toJavaList(String.class);
                return userMapper.selectUserIdsByRoleIds(roleIds);
            }

            default:
                throw new IllegalArgumentException("未知的审核人策略: " + strategy);
        }
    }

    /**
     * 沿组织树上溯N级
     */
    private String findSuperiorOrg(String orgId, int level) {
        String currentOrgId = orgId;
        for (int i = 0; i < level; i++) {
            BaseOrg org = orgMapper.selectById(currentOrgId);
            if (org.getParentId() == null) break;
            currentOrgId = org.getParentId();
        }
        return currentOrgId;
    }
}
```

### 7.2 各高级段类型的生成算法

#### FR-CODE-001: 数字流水段

```
输入: segment配置 + 关联前段值(prefix)
输出: 格式化数字字符串(如 "001", "0123")

算法:
1. 确定 prefix:
   - LINK_PREV_SEGMENT = '1' → 取前一段的生成值作为prefix
   - LINK_PREV_SEGMENT = '0' → prefix = ""

2. 查询 MDM_CODE_RECORD 表:
   SELECT CURRENT_VALUE FROM MDM_CODE_RECORD
   WHERE SCHEME_ID = #{schemeId} AND SEGMENT_ID = #{segmentId} AND PREFIX = #{prefix}
   FOR UPDATE  -- 行级锁保证并发安全

3. 若记录不存在:
   - current = START_VALUE (默认1)
   - 插入新记录
   若记录存在:
   - current = CURRENT_VALUE + STEP_VALUE (默认1)

4. 更新 CURRENT_VALUE = current

5. 格式化:
   - 将current转为字符串
   - 左补零至DIGIT_COUNT位
   - 返回格式化结果(如 DIGIT_COUNT=4, current=23 → "0023")
```

**并发安全**：利用 `MDM_CODE_RECORD` 的 `UNIQUE INDEX(SCHEME_ID, SEGMENT_ID, PREFIX)` + `FOR UPDATE` 行锁保证流水号不重复。

#### FR-CODE-002: 字母流水段

```
算法:
1. 同数字流水段获取prefix和记录
2. 当前值转为字母: 1→A, 2→B, ..., 26→Z, 27→AA, 28→AB, ...
3. 字母转换函数:
   toLetters(n):
     result = ""
     while n > 0:
       n -= 1
       result = (char)('A' + n % 26) + result
       n = n / 26
     return result
4. 步长递增: current += stepValue
5. 返回字母字符串(如 "A", "B", ..., "Z", "AA")
```

#### FR-CODE-003: 首字母流水段

```
输入: segment配置 + 主数据当前值
输出: 首字母+数字流水(如 "BJ001")

算法:
1. 从REF_ATTRIBUTE_ID关联的属性中取值
2. 提取首字母:
   - 中文: 使用pinyin4j库取拼音首字母(如"北京"→"BJ")
   - 英文: 直接取首字母(如"Apple"→"A")
3. 首字母部分作为prefix
4. 追加数字流水号(算法同FR-CODE-001, prefix=首字母)
5. 拼接: prefix + 格式化流水号(如 "BJ" + "001" = "BJ001")
```

#### FR-CODE-004: 时间戳段

```
算法:
1. 取服务器当前时间 LocalDateTime.now()
2. 按TIMESTAMP_FORMAT格式化:
   - "yyyyMMdd" → "20260527"
   - "yyyyMM"   → "202605"
   - "yyyy"     → "2026"
   - "yyyyMMddHHmmss" → "20260527143025"
3. 返回格式化字符串
```

#### FR-CODE-005: 随机码段

```
RANDOM_TYPE = UUID:
  返回 UUID.randomUUID().toString().replace("-", "")
  结果: 32位十六进制字符串

RANDOM_TYPE = TIMESTAMP_RANDOM:
  timestamp = System.currentTimeMillis()  // 13位
  random = Random.nextInt(900000) + 100000  // 6位随机数
  返回 Long.toHexString(timestamp) + Integer.toHexString(random)
  结果: 约16位十六进制字符串
```

#### FR-CODE-006: 表达式段

```
EXPR_TYPE = BEANSHELL:
  1. 构建上下文变量: 主数据字段值 + 系统变量
  2. 使用BeanShell解释器执行 EXPR_VALUE
  3. 返回执行结果字符串

EXPR_TYPE = SQL:
  1. 替换SQL中的变量占位符
  2. 执行SQL查询, 取单行单列结果
  3. 返回结果字符串
```

#### FR-CODE-007: 引用值段

```
算法:
1. 从REF_ATTRIBUTE_ID关联的属性取当前值
2. 值为空时:
   - EMPTY_ACTION = 'SKIP' → 返回空字符串(不影响编码拼接)
   - EMPTY_ACTION = 'ERROR' → 抛出异常
   - EMPTY_ACTION = 'DEFAULT' → 使用DEFAULT_EMPTY_VALUE
3. LINK_PREV_SEGMENT = '1' → 该值作为后续流水段的prefix
4. 返回属性值字符串
```

#### FR-CODE-008: 层级码段

```json
// HIERARCHY_CONFIG 示例
{
  "levels": [2, 2, 3],
  "separator": ".",
  "parentCode": "01.02"
}
```

```
算法:
1. 层级码独立成规则，不与其他段类型混用
2. 根据 parentCode 和 levels 计算子编码:
   - parentCode = "01.02", levels = [2, 2, 3]
   - 当前在第二层，子级在第三层(长度3)
   - 查询同级已有编码: SELECT MAX(CODE) ... LIKE '01.02.%'
   - 下一级编码 = "01.02.001"
3. 格式: 每层补零到指定位数，用separator连接
   - "01" → 1级(2位)
   - "01.02" → 2级(2位.2位)
   - "01.02.001" → 3级(2位.2位.3位)
```

### 7.3 段间关联的实现方案

段间关联通过 `LINK_PREV_SEGMENT` + `MDM_CODE_RECORD.PREFIX` 实现：

```
编码方案: SUP + 2026 + 001
          │       │      │
       固定段   时间段  数字流水段(LINK_PREV_SEGMENT='1')

执行顺序:
1. FIXED段 → "SUP" (prefix="")
2. TIMESTAMP段 → "2026" (prefix="SUP")
3. SEQUENCE段 → prefix = "SUP2026" (前两段拼接)
   → 查询MDM_CODE_RECORD WHERE PREFIX='SUP2026'
   → 得到 "001"

当年份变化(2027):
3. SEQUENCE段 → prefix = "SUP2027"
   → PREFIX变化 → 流水号重新从001开始
```

### 9.1 重试机制

#### 9.1.1 两级重试架构

```
┌─────────────────────────────────────────────────┐
│               接口级重试                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │ 组件A    │  │ 组件B    │  │ 组件C    │      │
│  │ ┌──────┐│  │ ┌──────┐│  │ ┌──────┐│      │
│  │ │组件级││  │ │组件级││  │ │组件级││      │
│  │ │重试  ││  │ │重试  ││  │ │重试  ││      │
│  │ └──────┘│  │ └──────┘│  │ └──────┘│      │
│  └──────────┘  └──────────┘  └──────────┘      │
│                                                 │
│  整个流程失败后 → 接口级重试(重新执行全流程)     │
│  接口级重试次数: RETRY_COUNT                    │
│  接口级重试间隔: RETRY_INTERVAL (秒)            │
└─────────────────────────────────────────────────┘
```

**重试执行逻辑**：

```java
/**
 * 分发执行(含重试)
 */
public void executeDistributeWithRetry(String distId, List<String> dataIds) {
    MdmEsbModelDist dist = getDistById(distId);
    int compRetryCount = dist.getCompRetryCount();
    int compRetryInterval = dist.getCompRetryInterval();
    int ifaceRetryCount = dist.getRetryCount();
    int ifaceRetryInterval = dist.getRetryInterval();

    for (int ifaceAttempt = 0; ifaceAttempt <= ifaceRetryCount; ifaceAttempt++) {
        boolean allSuccess = true;

        // 逐组件执行
        for (EsbComponent component : getComponents(distId)) {
            boolean compSuccess = false;
            for (int compAttempt = 0; compAttempt <= compRetryCount; compAttempt++) {
                try {
                    executeComponent(component, dataIds);
                    compSuccess = true;
                    break;
                } catch (Exception e) {
                    log.warn("组件{}执行失败(第{}次)", component.getName(), compAttempt + 1, e);
                    if (compAttempt < compRetryCount) {
                        Thread.sleep(compRetryInterval * 1000L);
                    }
                }
            }
            if (!compSuccess) {
                allSuccess = false;
                break;
            }
        }

        if (allSuccess) return; // 全部成功

        // 接口级重试
        if (ifaceAttempt < ifaceRetryCount) {
            log.info("接口级重试(第{}次), {}秒后执行", ifaceAttempt + 1, ifaceRetryInterval);
            Thread.sleep(ifaceRetryInterval * 1000L);
        }
    }

    // 所有重试耗尽 → 记录异常 + 触发通知
    handleDistributeFailure(distId, dataIds);
}
```

#### 9.1.2 指数退避策略

当 `RETRY_INTERVAL = 0` 时启用指数退避：

```
重试间隔 = baseInterval * 2^(attemptNumber - 1)
baseInterval = 5秒

第1次重试: 5秒后
第2次重试: 10秒后
第3次重试: 20秒后
最大间隔: 300秒(5分钟)
```

### 9.2 定时分发

#### 9.2.1 @Scheduled 定时任务

```java
/**
 * ESB定时分发调度器
 * 对应需求: FR-ESB-002
 */
@Component
@RequiredArgsConstructor
public class EsbScheduledDistributor implements DisposableBean {

    private final MdmEsbModelDistMapper distMapper;
    private final EsbService esbService;
    private final ThreadPoolTaskScheduler scheduler;
    private final Map<String, ScheduledFuture<?>> scheduledTasks = new ConcurrentHashMap<>();

    /**
     * 应用启动时加载所有定时分发任务
     */
    @PostConstruct
    public void initScheduledTasks() {
        List<MdmEsbModelDist> dists = distMapper.selectList(
            new LambdaQueryWrapper<MdmEsbModelDist>()
                .eq(MdmEsbModelDist::getSyncType, "TIMED")
                .eq(MdmEsbModelDist::getStatus, "启用"));

        for (MdmEsbModelDist dist : dists) {
            scheduleDistTask(dist);
        }
    }

    /**
     * 注册定时分发任务
     */
    public void scheduleDistTask(MdmEsbModelDist dist) {
        if (dist.getCronExpr() == null || dist.getCronExpr().isEmpty()) return;

        CronTrigger trigger = new CronTrigger(dist.getCronExpr());
        ScheduledFuture<?> future = scheduler.schedule(
            () -> executeTimedDist(dist), trigger);
        scheduledTasks.put(dist.getId(), future);
    }

    /**
     * 执行定时分发
     */
    private void executeTimedDist(MdmEsbModelDist dist) {
        // 1. 查询待分发的数据(受BATCH_SIZE限制)
        List<String> dataIds = getPendingDataIds(
            dist.getModelId(), dist.getBatchSize());

        if (dataIds.isEmpty()) return;

        // 2. 执行分发(含重试)
        esbService.executeDistribute(dist.getId(), dataIds);
    }

    /**
     * 刷新定时任务配置
     */
    public void refreshTask(String distId) {
        // 取消旧任务
        ScheduledFuture<?> old = scheduledTasks.remove(distId);
        if (old != null) old.cancel(false);

        // 重新注册
        MdmEsbModelDist dist = distMapper.selectById(distId);
        if ("TIMED".equals(dist.getSyncType()) && "启用".equals(dist.getStatus())) {
            scheduleDistTask(dist);
        }
    }

    @Override
    public void destroy() {
        scheduledTasks.values().forEach(f -> f.cancel(false));
        scheduledTasks.clear();
    }
}
```
